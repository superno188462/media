## 2. 定：目标、用户与价值

### REQ-01 学习目标

开发者能沿需求、契约、骨架、测试、实现的链路，解释并独立完成一个小型 DSH 插件；能区分 DSH 原生能力、业务插件、Skill 和 MCP；能把通用能力迁移到第二个项目。

### REQ-02 产品目标

“内卷树懒”是一个疲惫、毒舌、但认真交付的 AI 创作者。首期交付一个可恢复的图文审核发布流程：

`DSH 准备内容 → 保存草稿 → 飞书展示完整审核内容 → 授权人批准 → 后台自动投稿 → 核对平台结果 → 发送回执`。

### REQ-03 使用者

| 角色 | 权限与主要任务 |
| --- | --- |
| 开发者 / 运营者 | 配置 DSH、账号和审核人；创建、修改、送审草稿；查看结果与处理阻塞 |
| 授权审核人 | 在已配置的飞书组织和会话中查看内容，批准或退回指定版本 |
| DSH Agent | 生成候选内容、调用受限草稿工具；无权自行批准或绕过审核直接发布 |
| 后台发布执行器 | 持有经验证的审核授权，执行指定账号和版本的投稿 |

## 3. 拆：首期用户流程

### REQ-04 创建和修改草稿

运营者在 DSH 中要求准备一篇图文。DSH 可生成文字并使用已有素材；图像生成提供方尚未选定，允许先使用人工准备的图片完成闭环。系统导入图片为受控资产，保存目标账号、完整正文、图片顺序、公开范围、AI 声明和人设版本。

草稿有稳定 ID 和递增版本。内容必须能持久保存，不依赖模型记住“刚才那篇”。已送审内容修改后，旧审核失效；已批准的版本被冻结。

### REQ-05 送审

运营者将草稿送审。审核消息包含目标账号、版本、完整文字与全部图片的可访问预览、公开范围、AI 声明，以及“通过并发布”“退回修改”“取消审核”。

如飞书卡片无法容纳完整内容，必须附经身份校验的只读预览入口；不得用可能改变含义的摘要替代完整审核内容。只有通知被发送不代表用户已审核。

### REQ-06 批准与自动发布

只有服务端配置的审核人可作决定。回调经来源验证并校验草稿版本、摘要与有效期后，持久化批准和发布任务。审核人一次“通过并发布”就是该账号、该版本、该公开范围的发布授权。

批准后无需回 DSH 再确认。执行器只能发布被批准的内容，不得临时让模型改标题、换图、加话题、换账号或改变 AI 声明。

### REQ-07 退回、取消和到期

退回可附修改意见，取消和到期不产生发布任务。运营者修改后重新送审。旧卡片即使仍可点击，也不能使旧版本重新获得授权。

### REQ-08 发布结果

区分“已上传素材”“已提交平台”“公开发布已确认”。只有能核对目标账号、内容及平台状态的证据才可标为已发布；结果不明确显示“结果待确认”，禁止把点击成功或 HTTP 200 当作发布成功。

### REQ-09 中断与恢复

登录过期、验证码或页面不兼容时暂停并通知。运营者处理登录后，可恢复已知尚未提交的任务。提交后超时或进程崩溃时先核对平台，不能盲目重发。重复审核回调和重复点击不会创建第二个逻辑发布任务。

## 4. 配：本期组件与边界

### REQ-10 DSH 优先

复用 DSH 的 Agent 循环、模型配置、工具注册、会话和原生界面扩展点。业务插件负责草稿、审核与状态；外部平台能力由适配器承接。第一版不自建聊天前端或第二套 Agent 主循环，也不要求先建通用 FastAPI 网关。

### REQ-11 依赖可替换

抖音投稿插件、飞书 SDK、模型提供方均通过应用服务边界接入。Skill 是操作规则，不自动等同于可调用服务；MCP 是协议，不自动等同于完整业务系统。原生投稿插件若已足够，不强制再包一层 MCP。

### REQ-12 数据与授权隔离

首期一个运行实例、一个工作区、一个人设和一个平台账号（抖音与 B站同为规划范围，首期先落地 B站，见 [CHANGE-001](../governance.md)）。契约保留 `workspace_id`，但这不代表已实现安全的多租户系统。凭据保存在服务端；预览不可泄漏 Cookie、API Key、内部路径或其他工作区素材。

## 5. 本稿提出的产品默认值

下表是待评审的产品限制，不是抖音、B站或飞书官方限制。平台限制更严格时，适配器提前拒绝，不静默截断。

| 项目 | 提议 |
| --- | --- |
| 首期内容 | **图文**：1–9 张 JPEG/PNG，单张 ≤10 MiB，宽高各 ≤8192 px；**视频**：1 个 MP4（H.264），≤100 MiB，时长 ≤10 分钟，宽高各 ≤8192 px。平台：B站优先（bilibili），抖音同期规划。视频见 [CHANGE-002](../governance.md) |
| 文字 | 标题 1–80 字符；正文 1–1000 字符；字符按 Unicode 码点计算 |
| AI 声明 | 本项目首期内容统一声明 AI 生成；平台实际标识方式待验证 |
| 公开范围 | `public` 或 `private`，创建时显式选择并在审核中展示 |
| 审核有效期 | 发起后 24 小时，服务端时间等于截止时间时已失效 |
| 批准后首次提交期限 | 批准后 1 小时；超时且确认未提交则失败，重新创建草稿送审 |
| 运行方式 | 本机常驻 DSH 和插件，主机休眠期间不承诺执行 |
| 首期审核渠道 | 飞书自建应用机器人；企微作为后续适配器 |

## 6. 评：验收与成功定义

### REQ-13 功能验收

1. 用一条测试图文走完真实飞书送审和平台发布（首期 B站），回执能核对作品。
2. 未批准、退回、取消、过期或非审核人操作均不能发布。
3. 审核前后内容变更、重复回调和两个审核人并发操作有确定结果。
4. 登录失效后可见地阻塞；提交结果未知时不自动重复提交。
5. 在草稿、送审、已批准排队、提交中四个位置分别重启，表现符合 SDD。

真实发布仅在用户批准该测试内容后执行；这条验收定义不提前授权发布任何具体内容。

### REQ-14 学习验收

开发者能解释一次工具调用经过哪些层，能用假投稿适配器替换真实抖音，能在不改审核规则的情况下替换内容人设，并能为新增字段完整走一遍契约变更流程。

### REQ-15 记录指标

记录草稿数、送审数、批准/退回数、已提交/已发布/结果未知数、制作及发布耗时、可获得的模型用量。用量拿不到时记未知，不推算为零。不承诺涨粉、收入、零成本或全天候可用。

## 7. 延后范围

视频制作与视频 MCP、自动评论、用户画像和向量记忆、全网自动抓取、多个 IP 并行、多租户计费、独立商业客户端、企微审核及官方抖音 OAuth 接入均不属于本次行为基线。它们可在学习路线中规划，不进入首期必需依赖。
