# DSH 工作台与飞书审核交互基线

| 项目 | 内容 |
| --- | --- |
| 标识 / 版本 | UI-CS / `0.1.0-draft.1` |
| 状态 / 日期 | 用户确认当前交互方向 / 2026-10-26 |
| 关联需求 | [PRD-CS](prd.md)，REQ-04—REQ-10 |
| 确认依据 | 用户在上一轮请求评审后回复“继续”；具体宿主挂载方式须由 SDD 与实测落实 |

## UI-01 信息架构

DSH 原生会话用于创作和下达指令，拟新增一个“内卷树懒”插件入口。入口采用所选 DSH 版本实际支持的原生侧栏或插件设置扩展，不假设已经存在固定路由或注册 API。

```text
DSH 原生界面
├─ 原生会话：选题、写稿、修改意见
└─ 内卷树懒
   ├─ 任务列表：草稿 / 待审核 / 发布任务
   ├─ 草稿详情：完整内容、版本、审核记录、发布状态
   └─ 接入状态：DSH、飞书、抖音登录与能力检查

飞书
└─ 审核卡片 → 完整预览 → 通过并发布 / 退回修改 / 取消审核
```

不另建登录系统和聊天产品。只读完整预览页是卡片长度不足时的备选，并非必须单独部署的网站。

## UI-02 工作台线框

```text
内卷树懒                                      [刷新]
筛选：全部 / 草稿 / 待审核 / 发布任务
----------------------------------------------------
标题             账号        版本    状态         时间
今天也在加班     树懒账号     v2     等待审核     09:10
----------------------------------------------------
详情：今天也在加班                            [返回]
目标账号 / 人设版本 / 可见范围 / AI 声明
完整标题与正文
[图1] [图2] ...（显示顺序号，可逐张放大）
当前审核记录：谁、何时、批准了哪个版本
发布状态：排队 / 阻塞 / 已提交 / 已发布 / 结果待确认
操作：[送审] [取消审核] [处理登录后恢复] [核对结果]
```

修改内容通过 DSH 对话和草稿服务完成；首期不增加所见即所得编辑器。已批准版本的内容区域只读。

## UI-03 审核卡片线框

```text
内卷树懒 · 图文审核 · v2
目标：抖音 / 树懒账号      公开范围：公开
AI 声明：是               截止：北京时间 10-27 09:10
标题：今天也在加班
正文：完整正文，超长时明确标注“需打开完整预览”
图片：缩略图与顺序；全部原图可查看
[查看完整预览]
[通过并发布] [退回修改] [取消审核]
```

按钮文案必须包含“发布”，不能只写“看过了”。卡片展示内容摘要短码用于人工核对，但完整摘要由服务端校验。短码不是授权凭证。

## UI-04 关键交互

| 动作 | 用户看到什么 | 服务端结果 |
| --- | --- | --- |
| 送审 | 立即显示提交中，完成后展示审核 ID 和通知状态 | 创建审核记录；通知发送可异步完成 |
| 批准 | 显示“已批准，等待投稿”，禁用旧按钮 | 决定与任务持久化后返回成功；不宣称已发布 |
| 退回 | 填写可选修改意见，显示“已退回” | 不创建发布任务 |
| 取消 | 显示“审核已取消” | 尚未决议的审核被取消 |
| 改稿 | 新版本显示“需重新审核” | 旧审核失效 |
| 非审核人点击 | 明确“你没有此内容的审核权限” | 无状态变化、无发布副作用 |
| 旧卡片被点击 | 显示“版本已失效”及当前版本 | 不恢复旧授权 |
| 重复回调 | 保持已记录结果 | 不重复建立任务 |
| 发布阻塞 | 展示登录/验证码/能力不匹配等原因 | 发布前暂停，人工恢复条件明确 |
| 结果不明确 | 显示“请先核对抖音作品，暂不能重新提交” | 只允许核对，禁止重复发布 |

批准后自动执行；验证码、登录处理属于故障恢复，不把已批准内容重新送回运营者逐次确认。

## UI-05 全部界面状态

| 状态 | 展示与可用操作 |
| --- | --- |
| 初始 / 加载 | 有文本加载提示，禁用依赖数据的按钮 |
| 空列表 | “还没有草稿，请在 DSH 对话中准备第一条图文” |
| 成功 | 数据版本与更新时间可见，操作按服务端状态启用 |
| 待审核 | 完整内容只读展示，可取消审核；改稿导致新版本 |
| 可恢复错误 | 保留当前选中项和草稿；允许重新读取，不自动重新提交写操作 |
| 不可恢复错误 | 明确资源不存在、无权限或能力不支持，显示返回入口 |
| 取消 / 过期 | 展示原因与时间，可修改后重新送审 |
| 旧请求晚到 | 不覆盖新选中资源和较新服务端版本 |

## UI-06 视觉、设备与访问

沿用 DSH 组件、字体和主题，不另设计一套管理后台。桌面工作台在 1280×720 下可操作；飞书卡片及预览在 375 像素宽手机视口可阅读。图片保持比例，文字可换行，状态必须同时使用文字，不只用颜色。

自建界面按钮支持键盘聚焦和可见焦点，输入有标签，错误有文本。飞书宿主控件自身的可访问性由平台提供，真实验收时单独记录限制。

首期工作台只在本机可信 DSH 宿主内使用；完整预览若通过外部链接访问，必须有已验证的审核人身份和失效机制。GET 打开预览不能批准或发布，防止消息链接预取触发写操作。

## UI-07 操作映射

字段以 [共享 Schema](global_schema.md) 为准；操作以 [服务端 SDD](../backend/approval-publishing.spec.md) 为准。

| UI 操作 | 应用服务 |
| --- | --- |
| 列表 / 详情 | `listDrafts` / `getDraft` / `getPublishJob` |
| 送审 / 取消 | `requestReview` / `cancelReview` |
| 飞书按钮 | 飞书适配器验证来源后调用内部 `applyDecision` |
| 恢复登录阻塞 | 运营者触发 `resumePublish` |
| 核对结果 | `reconcilePublish`，只读核对平台状态 |
