# 飞书配置完整教程（从零开始）

这份文档假设你**从来没配置过飞书机器人**。按顺序做完，就能让「内卷树懒」把内容发到飞书群里等人审核。

> 全程约 20–30 分钟。中途需要**发布应用版本**，如果你的企业开启了管理员审核，
> 可能还要等管理员批准。
>
> 本机环境（Python、uv、项目代码）的准备见 [前期准备工作](preparation.md)。
> 本文只管飞书那边怎么点。

## 1. 先看懂 7 个词

配置过程中会反复出现这些词，先扫一眼，后面就不慌了。

| 词 | 通俗解释 | 类比 |
|---|---|---|
| **飞书开放平台** | 给开发者用的网站，在这里「造」机器人 | 应用商店的开发者后台 |
| **自建应用** | 你自己公司内部用的应用，不用上架 | 公司内部的工具 |
| **机器人（Bot）** | 应用的一个能力，能以「一个账号」的身份在群里说话 | 群里的一个成员 |
| **App ID / App Secret** | 机器人的账号和密码 | 用户名 / 密码 |
| **权限（Scope）** | 机器人被允许做什么 | 门禁卡的权限范围 |
| **回调（Callback）** | 用户点了按钮，飞书**主动来告诉你** | 门铃响了通知你有人来 |
| **长连接** | 我们的程序主动连到飞书，不用公网地址 | 你打电话过去，而不是等别人打来 |

另外两个后面会用的 ID：

| 词 | 长什么样 | 是什么 |
|---|---|---|
| `chat_id` | `oc_` 开头 | 某个**群**的编号 |
| `open_id` | `ou_` 开头 | 某个**人**的编号 |

## 2. 你需要有什么

- [ ] 一个飞书账号
- [ ] 属于某个「企业 / 团队」（个人版飞书也能创建自建应用，但部分能力受限）
- [ ] 在团队里有**创建应用**的权限（一般是管理员，或管理员给你开了开发者权限）
- [ ] 本机已按 [前期准备工作](preparation.md) 配好 Python 和项目代码

**不确定有没有权限？** 直接打开
[https://open.feishu.cn/app](https://open.feishu.cn/app) 试试点「创建应用」。
如果按钮是灰的或提示没权限，找你的飞书管理员开。

## 3. 第一步：创建应用

1. 浏览器打开 **https://open.feishu.cn/app**
2. 点右上角「**创建应用**」
3. 选择「**企业自建应用**」（不是「商店应用」）
4. 填：
   - **应用名称**：随便起，建议 `内卷树懒审核`（群成员能看到这个名字）
   - **应用描述**：一句话，比如「内容审核机器人」
   - **图标**：可跳过，后面能改
5. 点「**创建**」

**你会看到**：跳到应用详情页，左边一排菜单（凭证与基础信息、权限管理、事件与回调、版本管理与发布……）

> 💡 不同版本后台菜单名可能略有差异，但功能对应得上。找不到就往下看本文对应章节的描述。

---

## 4. 第二步：记下 App ID 和 App Secret

1. 左侧菜单点「**凭证与基础信息**」
2. 页面上有两个值：

| 字段 | 长什么样 | 说明 |
|---|---|---|
| **App ID** | `cli_` 开头，如 `cli_a1b2c3d4e5f6g7h8` | 公开的，不算秘密 |
| **App Secret** | 32 位随机串 | **这是密码**，只显示一次 |

3. App Secret 右边有「**显示**」图标和「**复制**」按钮，点复制

⚠️ **立刻保存 App Secret**。关掉页面后想再看，得点「重置」，旧的就作废了。

⚠️ **不要**把 App Secret 发到聊天里、截图里、或提交到代码仓库。
本文所有示例都用 `xxxxxxxx` 代替它。

## 5. 第三步：开启机器人能力

应用默认只是个「空壳」，要告诉飞书「这个应用要能当机器人用」。

1. 左侧菜单找「**添加应用能力**」（有的版本叫「应用能力」）
2. 找到「**机器人**」卡片
3. 点「**添加**」或「**开启**」

**你会看到**：机器人那一栏变成「已添加」。

> ❗ 不做这一步：机器人加不进群，也发不了任何消息。

## 6. 第四步：申请权限（最容易错）

这是整个配置里**最容易出错**的一步，请慢慢看。

### 6.1 需要开通哪些

左侧菜单点「**权限管理**」，在搜索框里逐个搜索下面四项并开通：

| 搜什么 | 全称 | 干什么用 | 必须吗 |
|---|---|---|---|
| `im:chat:readonly` | 获取群组信息 | 列出机器人所在的群、读群成员 | ✅ 必须 |
| `im:message:send_as_bot` | 以应用身份发消息 | 把审核卡片发到群里 | ✅ 必须 |
| `im:resource:upload` | 上传图片 | 卡片里显示配图 | 有图就必须 |
| `contact:user.id:readonly` | 通过手机号或邮箱获取用户 ID | 用邮箱查人的 `open_id` | 可选 |

**操作**：搜到后点右边的「**开通**」或「**申请权限**」。

### 6.2 ⚠️ 最关键：身份类型必须选「应用身份」

开通权限时，飞书会问你要哪种身份：

| 身份类型 | 什么意思 | 我们要哪个 |
|---|---|---|
| **应用身份**（tenant） | 机器人以「应用自己」的身份做事 | ✅ **要这个** |
| **用户身份**（user） | 代表某个真人用户做事 | ❌ 不要 |

**为什么**：我们的程序用的是「应用身份令牌」调用接口。只开了用户身份，
调用时会返回「应用尚未开通所需的应用身份权限」，看起来像没开权限，其实开错了类型。

**开通后怎么确认**：回到权限列表，点开那一项看详情，确认「身份类型」里
**应用身份**是勾上的。

### 6.3 常见失败现象

开通了但没生效，接口返回：

```json
{
  "code": 99991672,
  "msg": "Access denied. One of the following scopes is required: [im:chat:readonly, ...].
          应用尚未开通所需的应用身份权限：[im:chat:readonly, ...]"
}
```

**看到这句话，先怀疑两件事**：

1. 身份类型选成了「用户身份」
2. **没有发布版本**（见第六步）

## 7. 第五步：配置长连接回调

「回调」是：用户在卡片上**点了按钮**，飞书要能找到我们的程序。
我们选「长连接」，意思是**我们的程序主动连到飞书**，不需要公网地址。

### 7.1 先理解：回调 ≠ 事件订阅

这两个东西在同一个页面，但**不是一回事**：

| | 事件订阅（Events） | 回调（Callbacks） |
|---|---|---|
| 干什么 | 飞书通知你「发生了某件事」（有人发消息、有人进群） | 飞书通知你「用户点了卡片按钮」 |
| 我们要的 | 基本不需要 | ✅ **只要这个** |
| 我们要的那项叫 | — | **`card.action.trigger`** |

> ❗ **很多人在「事件订阅」列表里翻半天找不到 `card.action.trigger`，因为它在「回调配置」里。**

### 7.2 操作

1. 左侧菜单点「**事件与回调**」（有的版本分成两个菜单）
2. 先找「**订阅方式**」，选择「**长连接**」
   - 不要选「**请求地址**」（那需要公网 URL，我们没有）
3. 切到「**回调配置**」标签页
4. 点「**添加回调**」
5. 搜索并添加：**`card.action.trigger`**
   - 中文界面可能显示为「卡片回传交互」或「卡片按钮回调」
   - **实在搜不到就搜 `card`**，看列表里哪个是卡片相关的

### 7.3 如果控制台强制先订阅一个事件

有的版本要求「事件订阅」里至少有一项，才允许配回调。那就：

1. 先订阅一个**基本不会触发**的事件，例如：
   - 「机器人进群」`im.chat.member.bot.added_v1`
   - 或「机器人自定义菜单事件」`application.bot.menu_v6`
2. 配好回调、发版本、验证通过后，**再把这个事件删掉**（删完要再发一次版本）

> 为什么要删：我们代码只处理卡片按钮。订阅了不处理的事件，
> 每次触发都会让程序打一条错误日志（虽然不影响运行）。

## 8. 第六步：发布版本（最容易漏）

**飞书的规则：权限、回调、能力的任何改动，都要「发布一个新版本」才真正生效。**

很多人卡在这里：明明都配了，就是不工作。

### 操作

1. 左侧菜单点「**版本管理与发布**」
2. 点「**创建版本**」
3. 填：
   - **版本号**：如 `1.0.0`
   - **更新说明**：随便写，如「初始版本」
   - **可用范围**：选「**全员可用**」或指定的人（**建议选全员或至少包含审核人**）
4. 点「**保存**」→「**申请发布**」
5. 如果企业开了管理员审核，等管理员批准

**你会看到**：版本状态变成「**已发布**」。

> ❗ 状态如果是「审核中」或「待发布」，权限都还没生效。

**以后每次改权限/回调，都要重复这一步**（版本号递增即可）。

## 9. 第七步：建群并拉机器人进群

审核卡片要发到某个群里，所以机器人必须在那个群里。

1. 打开飞书客户端（电脑或手机都行）
2. 新建一个群，起名如「**内卷树懒审核群**」
3. 建议**只拉审核人**进群（群成员都能看到卡片内容）
4. 群右上角「**⋯**」→「**设置**」→ 找「**机器人**」→「**添加机器人**」
5. 搜索你刚才创建的应用名（如「内卷树懒审核」）
6. 添加

**你会看到**：机器人出现在群成员列表里。

> ⚠️ 如果搜不到机器人：说明第五步的机器人能力没开启，或第六步的版本没发布成功。

## 10. 第八步：拿到 chat_id 和 open_id

现在需要两个编号：群的和人的。

### 10.1 方法 A：用项目里的脚本（推荐）

先确认本机已按 [前期准备工作](preparation.md) 配好。

**① 拿群的 `chat_id`**

```powershell
cd D:\github\robot\services\feishu
uv run --with lark-oapi --no-project python scripts\whoami.py --list-chats
```

预期输出：

```
机器人所在群（1 个）：
  chat_id=oc_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx  name=内卷树懒审核群
```

把 `oc_...` 那串抄下来。

**② 拿审核人的 `open_id`**

```powershell
uv run --with lark-oapi --no-project python scripts\whoami.py --chat oc_你的chat_id
```

预期输出：

```
群 oc_xxx 成员（1 人）：
  open_id=ou_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxx  name=审核人昵称
```

把 `ou_...` 那串抄下来。

**③ 如果你知道审核人的邮箱，也可以直接换**

```powershell
uv run --with lark-oapi --no-project python scripts\whoami.py --email 对方邮箱@公司.com
```

> 这条需要 `contact:user.id:readonly` 权限。

### 10.2 方法 B：手动找（脚本用不了时）

**群的 chat_id**：在群里点「⋯」→「群设置」→ 找「群链接」→ 复制。
如果链接里含 `openChatId=oc_...`，那串就是。

> ⚠️ 如果复制出来是 `...add_by_link?link_token=...` 这种，那是**邀请链接**，
> **里面没有 chat_id**，用不了。这种情况还是用方法 A。

**人的 open_id**：飞书客户端一般不直接显示。建议用方法 A。

## 11. 第九步：写进本机配置

打开（没有就新建）：

```
D:\github\robot\.local\dsh\.credentials.yaml
```

在 `refs:` 下面加这四行（`FEISHU_TENANT_KEY` 可以稍后补）：

```yaml
refs:
  FEISHU_APP_ID: cli_你抄的AppID
  FEISHU_APP_SECRET: 你抄的32位Secret
  FEISHU_REVIEW_CHAT_ID: oc_你抄的群ID
  FEISHU_REVIEWER_OPEN_ID: ou_你抄的人ID
  FEISHU_TENANT_KEY: 先留空或稍后填
```

⚠️ 这个文件在 `.local/` 目录，已被 `.gitignore` 排除，**不会进代码仓库**。
但也**不要**把它发给别人或贴进聊天。

## 12. 第十步：验证能跑通

分三步验证，每步都要看到预期结果再往下。

### 12.1 验证凭证有效

```powershell
cd D:\github\robot\services\feishu
uv run --with lark-oapi --no-project python scripts\whoami.py --list-chats
```

- ✅ 能列出群 → 凭证和权限都对了
- ❌ 报 `99991672` → 回第四步查权限（身份类型 + 发版本）

### 12.2 启动监听，等按钮

```powershell
uv run --with lark-oapi --no-project python scripts\run_listener.py
```

预期输出：

```
监听启动 app_id=cli_xxx
  工作区 workspace=cyber-sloth
  状态存储 D:\github\robot\.local\approval
  审核会话 chat_id=oc_xxx
  审核人 allowlist=ou_xxx
  组织校验 tenant_key=（未配置，跳过）
等待卡片按钮动作…
```

**让它一直开着**（另开一个终端做下一步）。

### 12.3 发一张测试卡片

另开一个终端：

```powershell
cd D:\github\robot\services\feishu
uv run --with lark-oapi --no-project python scripts\send_draft.py `
  --title "测试卡片" `
  --body-file "D:\github\robot\.local\content\demo\body.txt" `
  --image "D:\github\robot\services\content\assets\posts\2026-10-26-demo.jpg" `
  --account-id "bilibili:<你的B站UID>"
```

预期：群里出现一张卡片，有标题、正文、配图、一个输入框、三个按钮。

**然后去飞书里点「取消审核」**。

回到监听终端，应该立刻出现：

```
DECISION {"action": "cancel", "review_id": "rv-...", "operator_open_id": "ou_...", ...}
```

飞书那边会弹一个小提示：「已取消审核」。

- ✅ 三处都对 → **配置完成**
- ❌ 点了没反应 → 看下一节

### 12.4 补上 tenant_key（建议）

上一步的 `DECISION` 日志里有 `"tenant_key": "..."`，把它填进配置文件：

```yaml
  FEISHU_TENANT_KEY: 你看到的那个值
```

重启监听器，启动信息会变成：

```
  组织校验 tenant_key=xxxxxxxxxxxxxxxx
```

这之后只有你组织的操作会被接受，更安全。

## 13. 出问题了怎么查

按**症状**找对应处理。

### 13.1 报 `99991672`

```
Access denied. One of the following scopes is required: [...]
应用尚未开通所需的应用身份权限
```

排查顺序：

1. 权限有没有开通？→ 第四步
2. 开通时身份类型是不是选了「**应用身份**」？→ 6.2
3. **有没有发布版本**？→ 第六步

### 13.2 点按钮弹「出错了，请稍后重试 code: 200671」

这不是权限问题。意思是**我们的程序收到回调但没给飞书回话**。

- 这属于代码问题，不是配置问题
- 本项目已修复：回调必须返回 `P2CardActionTriggerResponse`
- 如果你在改代码，注意这一点

### 13.3 点按钮完全没反应

1. 监听器还在运行吗？（终端有没有退出）
2. 订阅方式是不是「**长连接**」？→ 7.2
3. 回调里加了 `card.action.trigger` 吗？→ 7.2
4. 加完**发版本**了吗？→ 第六步

### 13.4 `whoami.py --list-chats` 返回空

机器人**没进群**。→ 第七步

### 13.5 卡片里图片是空白

- 图片上传权限 `im:resource:upload` 没开 → 第四步
- 或者代码传了本地路径而不是 `img_key`（本项目已处理）

### 13.6 找不到某个菜单

飞书后台版本不同，菜单名会变。按功能找：

| 你要做的 | 找含这些字的菜单 |
|---|---|
| 看 App ID/Secret | 凭证、基础信息 |
| 开机器人 | 应用能力、添加能力 |
| 开权限 | 权限管理 |
| 配回调 | 事件与回调、事件订阅 |
| 发版本 | 版本管理、发布 |

## 14. 速查：以后新开一个机器人

给已经做过一次、想再开一个的场景。

**平台侧**

- [ ] 创建企业自建应用，记下 **App ID** / **App Secret**
- [ ] 添加「**机器人**」能力
- [ ] 权限管理开通，**全部选应用身份**：
  - [ ] `im:chat:readonly`
  - [ ] `im:message:send_as_bot`
  - [ ] `im:resource:upload`
  - [ ] `contact:user.id:readonly`（可选）
- [ ] 事件与回调 → 订阅方式选 **长连接**
- [ ] 回调配置添加 **`card.action.trigger`**
- [ ] 版本管理与发布 → **创建版本 + 发布**
- [ ] 建群，把机器人拉进群

**本机侧**

- [ ] `whoami.py --list-chats` → 拿 `chat_id`
- [ ] `whoami.py --chat <chat_id>` → 拿 `open_id`
- [ ] 更新 `.local/dsh/.credentials.yaml` 四个键
- [ ] 重启 `run_listener.py`，确认打印的 `chat_id`/allowlist 正确
- [ ] 发一张测试卡片并点按钮，确认收到 `DECISION`
- [ ] 从 `DECISION` 里取 `tenant_key` 补进配置，重启

**好消息：代码一行都不用改。** 换机器人只需要换配置里的四个值 + 重启监听。

## 15. 附录

### 15.1 回调载荷长什么样（实测）

用户点按钮后，我们的程序收到：

```json
{
  "header": {"event_id": "...", "event_type": "card.action.trigger"},
  "event": {
    "operator": {"tenant_key": "...", "open_id": "ou_...", "user_id": "..."},
    "context": {"open_message_id": "om_...", "open_chat_id": "oc_...", "preview_token": "..."},
    "action": {
      "tag": "button",
      "name": "reject_btn",
      "value": {
        "action": "reject",
        "review_id": "rv-...",
        "revision": "1",
        "content_digest": "..."
      },
      "form_value": {"feedback": "退回意见原文"},
      "input_value": null
    }
  }
}
```

三个要点：

1. 输入框内容在 **`form_value.feedback`**，不是 `input_value`
2. 操作者身份只信 `operator`，**不能让别人自己报**
3. `review_id`/`revision`/`content_digest` 是发卡片时写进去的，
   用来验证「批准的是哪一版内容」

### 15.2 审核卡片的结构

```
标题
版本 / 草稿 ID / 内容摘要
目标账号
────────────
完整正文
────────────
配图（每张一个图，用上传后的 img_key）
────────────
表单
  ├─ 输入框（退回意见，最多 500 字）
  ├─ 按钮：通过并发布
  ├─ 按钮：退回修改
  └─ 按钮：取消审核
────────────
提示：通过后由后台自动投稿
```

**必须用「表单」把输入框和按钮包在一起**，按钮设成「提交表单」，
否则输入框里的字不会跟按钮一起传回来（实测过，不包表单就收不到）。

### 15.3 三个按钮分别是什么意思

| 按钮 | 意思 | 意见框 |
|---|---|---|
| 通过并发布 | 内容合格，批准发布 | 忽略 |
| 退回修改 | 内容要改，可以写意见 | 采纳，1–500 字 |
| 取消审核 | 撤回这次送审，不代表内容有问题 | 忽略 |

「退回修改」和「取消审核」的区别：
前者是「内容有问题」，后者是「先不审了」。审计上要能分开。

### 15.4 已知限制

- **卡片里不能播放视频**。视频审核需要另做方案（关键帧 + 只读预览入口），
  目前在 [CHANGE-002](../specs/governance.md) 待评审。
- 审核**24 小时**有效；批准后**1 小时内**必须提交，超时要重新送审。
- 卡片预览被人点开**不会**触发任何批准，只有真实按钮动作才算。
- 本机没有公网地址，只能用长连接。
